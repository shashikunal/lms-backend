Enterprise API Reference — audited Oct 2026

LMS Course Marketplace API Documentation

Digital-course marketplace: browse, buy with Razorpay, enroll, learn with progress, earn certificates. No shipping, no cart, no inventory. Every endpoint below was live-verified (104/104).

Version: 2.0.0
Base URL (Prod): https://mockapi-mauve.vercel.app
Base URL (Dev): http://localhost:8000
Swagger UI: /api-docs
OpenAPI JSON: /api-docs.json

Auth & roles

JWT Bearer or cookies. Roles: student (user), instructor (courses + revenue), admin (approvals, users, analytics).

Digital purchase

Course → Buy Now → Razorpay create/verify (HMAC) → order → enrollment → Go to Course.

Enrollment-gated learning

Preview lectures open; locked content needs enrollment. Progress per lecture; 100% auto-issues a certificate.

Instructor marketplace

Create as DRAFT, build curriculum, submit, admin publishes. Revenue, students and analytics included.

8. Verification report (live audit, Oct 2026)

104 / 104 checks passed

Every route above was called against a live server with real DB: public reads, auth gating (401/403), role gating, happy paths (200/201) and error paths (400/404). Test data was removed afterwards.

Fixed during audit

Order/Q&A mails no longer 500 or hang when SMTP is down (best-effort); progress completion now persists (certificate auto-issues at 100%); section routes resolve by lecture id or title; refresh/activate return 400 (not 500) for bad tokens; register still returns credentials with mailSent:false.

Environment notes

SMTP (Ethereal) creds in .env were expired at audit time — mails are skipped, flows still succeed. Avatar/banner uploads need Cloudinary keys. Razorpay uses a dev fallback order when keys are placeholders; verification is always HMAC-checked.

Removed surface

Old physical-commerce APIs (/product, /cart, /address, /ecommerce/order, /product-reviews + shop category/coupon/payment/wishlist) return 404 by design. Use /api/v1/lms/* instead.
